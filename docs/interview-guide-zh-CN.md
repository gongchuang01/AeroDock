# AeroDock 项目讲解与面试指南

这份文档用于帮助你准确介绍已经在仓库中实现和验证的内容。面试时应根据自己的实际理解作答，不要背诵不理解的术语。

## 简历项目描述

**AeroDock：基于 ROS 2 与 PX4 的无人机自主航点及激光雷达避障系统**

- 基于 ROS 2 Humble、PX4 v1.16 和 Gazebo Harmonic 搭建无人机 SITL 仿真系统，使用 C++17 实现 Offboard 任务状态机，完成解锁、起飞、多航点巡航、返航和降落。
- 实现基于二维激光雷达的局部避障规划器，通过扇区距离统计、多帧持续性过滤和左右净空对比生成临时绕行点，绕障后自动恢复原航线。
- 增加独立紧急降落监督器、CSV 遥测记录和七项自动验收；集成仿真完成 5/5 航点，绕行点最小误差 0.20 m，降落后高度 0.07 m。
- 通过 GitHub Actions 执行规划器单元测试、遥测回归验收、Shell 语法检查、ROS 2 干净编译和 Docker 构建，并保留可重现的飞行数据与可视化图表。

## 30 秒概述

AeroDock 是我用 ROS 2 和 PX4 做的无人机自主飞行仿真项目。它不只能执行固定航点，还会读取激光雷达，在航线被阻挡时动态插入绕行点，绕过障碍后再恢复原航线。我还实现了安全监督、飞行遥测和自动验收，最终完成了一次 5 航点、7 项验收全部通过的集成仿真。

## 3 分钟介绍结构

1. **问题**：固定航点任务无法处理航线上突然出现的障碍物，并且 Offboard 控制需要稳定的设定值流和明确的故障处理。
2. **架构**：Gazebo 提供物理环境和激光雷达，`ros_gz_bridge` 将扫描传入 ROS 2，局部规划器生成 NED 绕行点，C++ 任务节点通过 PX4 消息接口持续发送 Offboard 设定值。
3. **核心算法**：从前、左、右三个扇区提取有效距离，通过多帧确认抑制噪声，比较两侧净空后选择方向，将机体坐标系绕行偏移转换到 NED 地固坐标系。
4. **状态协同**：任务控制器保存被中断航点，执行临时 detour；绕行点稳定到达后恢复原目标，避免重复触发和航线丢失。
5. **验证**：不只看画面，而是记录时间、状态、航点、位置、目标和误差，再自动判断航点、绕行、高度与降落是否合格。
6. **结果**：完成 5/5 航点、7/7 验收，数据、图表、构建过程都保留在公开仓库中。

## 最值得讲的难点

### 1. ENU、NED 与机体坐标系

ROS 生态常见 ENU，PX4 本地位置与 Offboard 控制使用 NED，激光雷达数据还受传感器安装角和机体航向影响。如果直接把扫描平面的左右偏移当作地固坐标，无人机转向后就会飞向错误方向。项目通过航向旋转将机体偏移转换为 NED 目标。

### 2. 传感器噪声与误触发

单帧最小距离很容易受无效值、边缘点和短暂噪声影响。规划器先过滤非有限值与越界量程，然后对扇区距离使用稳健统计，并要求障碍在多帧扫描中持续出现。

### 3. 规划器与任务状态机的协作

绕行点不能破坏原有航点序列。控制器在接受 detour 时记住原目标，只在位置误差进入容差且持续一段时间后才恢复航线。这个“空间容差 + 时间稳定”条件可以避免在阈值边缘反复切换。

### 4. 小内存虚拟机的仿真稳定性

完整的 PX4、Gazebo、DDS 和 ROS 2 图形工具对资源要求较高。项目提供无头模式、降低雷达采样数与频率，并将物理仿真、图形可视化和遥测验收分开，使 4 核、8 GB 内存的虚拟机也能完成验证。

## 常见面试追问

### 为什么选择 ROS 2 和 PX4？

ROS 2 适合组织感知、规划、可视化和工具链；PX4 负责飞行器姿态、位置控制和底层飞控逻辑。两者通过 uXRCE-DDS 通信，可以让上层算法与底层飞控解耦。

### Offboard 模式为什么需要预先发送设定值？

PX4 要先确认外部控制器能持续提供有效控制流，才允许切换到 Offboard。因此状态机先进入 `PRESTREAM`，稳定发送设定值后再请求模式切换与解锁。

### 如果雷达消息中断怎么办？

安全监督器监测心跳、位置和关键数据时效性。超时或任务节点异常时，可以向 PX4 发送降落命令。对真实飞行器还需要飞控级失联策略、地理围栏和严格的实机测试。

### 为什么不直接使用完整 SLAM 或全局路径规划？

这个项目的边界是“已知航点任务中的局部突发障碍”。二维雷达局部绕行可以用更小的计算量把感知、坐标转换、状态机和验收链路做完整。如果场景扩展到复杂未知环境，再引入建图、三维占据和全局规划更合理。

### 你如何证明避障真的发生了？

验收不依赖人工观察。CSV 中记录了 `DETOUR` 状态、临时目标和误差；验收脚本要求 detour 曾出现、其最小误差进入 0.50 m 容差，同时全部原始航点仍被完成，最后进入降落状态且高度接近地面。

## 如实说明边界

- 当前局部规划是规则型算法，并非基于优化的轨迹规划器。
- 传感器为仿真二维激光雷达，未覆盖复杂三维障碍、定位漂移和真实风场。
- Docker 复现上层 ROS 2 构建与算法测试，完整 Gazebo/PX4 图形化仿真仍在 Ubuntu 22.04 中运行。
- 项目已通过 SITL 验证，不等于可直接部署到真实无人机。

能清楚说出这些边界，比将项目描述成“已完全解决自主飞行”更能体现工程判断力。
